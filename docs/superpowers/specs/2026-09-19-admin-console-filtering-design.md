# 管理后台筛选与表格优化 设计文档

日期：2026-09-19
状态：已获批准，待实施

## 一、背景与目标

管理后台的三个数据页（全局拉取、镜像统计、IP 分析）目前的表格是手写的最小实现，筛选能力残缺：全局拉取无法按用户或时间段筛选、表格里看不到用户；「类别」下拉在移除 GitHub/HF 加速时被清空，只剩一个「全部类别」；IP 分析看不到某个 IP 关联了哪些用户。此外「层/请求」这一列对使用者没有价值。

本次做五件事：

1. 全局拉取与镜像统计支持**时间段**筛选（预设 + 自定义起止）
2. 全局拉取支持**用户多选**筛选，表格显示用户
3. IP 分析新增**用户**列（多用户共用同一 IP 是关键滥用信号）
4. IP 筛选改为**前缀自动补全**；「类别」拆成**来源（registry）**与**类型（category）**两个下拉
5. **删除「层/请求」列**；三个表格的呈现做精化

**硬约束**：用户通过替换 Docker 镜像升级，沿用同一个 SQLite 文件。因此不得有任何破坏性的结构变更。

## 二、决策记录

| 议题 | 决定 | 理由 |
|---|---|---|
| 表格实现方式 | **不引入任何前端依赖**，继续手写 | 前端目前没有表格库。而所需筛选（IP 前缀补全、用户多选、时间段、枚举下拉）都是业务控件，**任何表格库都不自带**；库能省的只是表壳（当前 86 行），却会改变「风格类似」这一要求 |
| 用户名解析 | **服务端解析**，不走前端 id→名字映射 | 两个页面做法一致，前端不必维护映射表，也不会出现映射不全的问题 |
| `user_id` 为空的行 | 显示为**「匿名」** | 匿名拉取（未带令牌）与 `user_id` 列存在之前的历史行都为 NULL，必须有明确表示，不能留空白或显示 0 |
| 时间范围 | 预设区间 **+** 自定义起止 | 日常排查用预设，特殊情况手填 |
| 用户筛选 | **多选** | 排查滥用时需要一次看多个可疑账号 |
| 筛选维度 | 来源与类型**两个下拉都保留** | 二者是不同维度且后端都已支持，合并没有收益 |

### 被否决的选项

- **引入无样式表格库（TanStack Table）**：仍要自己写全部筛选控件，却要重写三个页面的表格结构，并把一个外部依赖引入一个刻意保持零 UI 依赖的项目。
- **引入完整 UI 套件（Element Plus 等）**：外观与现有后台差异明显，与「风格类似」直接冲突。

## 三、数据与后端

### 3.1 无需数据库结构变更

所需字段全部已存在：`pull_sessions.user_id`（已由 `ensureColumns` 经 `ALTER TABLE` 添加）、`started_at`、`registry`、`category`。所有新查询都是只读。`migrate()` 不需要改动，**换镜像升级是安全的**。

### 3.2 `PullListFilter`：单用户 → 多用户

`src/db/stats.go` 的 `PullListFilter.UserID int64` 改为 `UserIDs []int64`，SQL 由 `user_id = ?` 改为 `user_id IN (?,?,…)`。空切片表示不筛选。

**两个调用方都要改**（遗漏任一即编译失败，这是安全的失败方式）：

- `src/handlers/admin.go` 的 `AdminListPulls` —— 从 query 解析多值
- 用户控制台的「我的拉取」处理器 —— 传 `[]int64{当前用户ID}`

### 3.3 用户名在服务端解析

- **`ListPullSessions`**：`LEFT JOIN users` 补出 `PullSession.Username`。为 NULL 时前端显示「匿名」。
- **`ListIPStats`**：对当前页的 IP 集合追加一次聚合查询，取出每个 IP 关联的 `user_id` 集合，再解析为用户名，写入 `IPStat.Users []string`。

两处都用 `LEFT JOIN` / 可空处理，**不得使用 INNER JOIN**——那会让匿名行和已删除用户的行整条消失。

已删除用户（`pull_sessions.user_id` 指向不存在的 users 行）解析不到名字，显示为 `#<id>`。

### 3.4 新增端点：IP 前缀建议

```
GET /api/admin/ips/suggest?prefix=<前缀>
→ { "items": ["1.2.3.4", "1.2.3.45", ...] }   最多 10 条
```

只读、admin-only、按 `client_ip` 前缀匹配并去重排序。前缀为空时返回空数组而不是全部 IP。

### 3.5 「层/请求」只从界面移除

`layer_count` / `request_count` 的**存储、API 返回、内部计数逻辑一律不动**——它们仍被 `countedPullSQL` 等判定逻辑使用。仅删除 `PullsPage.vue` 中该列的 `<th>` 与 `<td>`。

## 四、前端

### 4.1 新增三个小组件

均无第三方依赖，与现有 `components/ui/*` 风格一致：

| 组件 | 用途 |
|---|---|
| `MultiSelect.vue` | 带勾选的下拉，用于用户多选 |
| `Autocomplete.vue` | 输入时展示前缀匹配建议，用于 IP |
| `DateRange.vue` | 预设区间 + 「自定义」展开起止日期 |

`DateRange.vue` 的预设：今天 / 近 7 天 / 近 30 天 / 全部 / 自定义。对外输出 `from`/`to` 两个 RFC3339 字符串，与现有 API 参数一致。

### 4.2 三个页面的表格

| 页面 | 新增列 | 筛选控件 |
|---|---|---|
| 全局拉取 | **用户** | IP（补全）、镜像名、用户（多选）、来源、类型、时间段 |
| 镜像统计 | 不加用户列（一个镜像可被多人拉取） | 镜像名、来源、类型、时间段 |
| IP 分析 | **用户**（多个用户时高亮提示） | IP（补全）、时间段 |

`ListImageStats` 需要新增 `From`/`To` 参数以支持时间段。

### 4.3 「精致」拆成可验收项

不使用形容词，逐条列出：

- 数字列右对齐并加 `tabular-nums`
- 所有单元格内边距统一
- 行悬浮态
- 长镜像名截断并加 `title` 属性
- **空态与加载态**（现状是两者都显示为空白行）
- 保持表头吸顶

## 五、兼容与迁移

- 无 schema 变更、无数据回填，换镜像即可升级。
- API 为**新增字段**（`PullSession.Username`、`IPStat.Users`），不改动既有字段语义，旧前端不受影响。
- `PullListFilter` 的字段改名是**编译期**破坏，不影响运行时兼容性。
- 筛选参数保持向后兼容：现有 `ip` / `image` / `category` / `registry` / `status` / `from` / `to` 语义不变，新增 `user_id`。

**多值参数形式（明确约定，避免实现歧义）**：`user_id` 重复出现，用 `c.QueryArray("user_id")` 读取，形如 `?user_id=2&user_id=5`。**不**同时支持逗号分隔——两种形式都收会带来不必要的解析分支与测试面。缺省或空数组表示不按用户筛选。

## 六、验证

**Go 单测**（新增）：

- 多用户 `IN` 过滤：选中两个用户时只返回这两人的记录
- 匿名行（`user_id` 为 NULL）在筛选与展示中都被正确保留
- IP 用户聚合：同一 IP 关联多个用户时全部返回；匿名行不产生用户名
- suggest 端点：前缀匹配、上限 10 条、空前缀返回空数组

**前端**：`npm run build`（含 `vue-tsc` 类型检查）。

**人工**：三个页面的筛选组合与表格观感需在浏览器中确认——本环境无浏览器。

## 七、明确不做

- 不引入任何前端依赖
- 不改变 `layer_count` / `request_count` 的存储与 API 返回
- 不做数据库结构变更或数据回填
- 不给镜像统计页加用户列
- 不做表格排序、列显隐、导出等库能力
- 不改动用户控制台「我的拉取」的既有观感（仅改其调用 `PullListSessions` 的传参方式）
